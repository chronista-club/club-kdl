## 方針

仕様 02 の短縮参照記法を、既存パーサーの上にある composer に実装する。名称は[仕様 02 の用語](../spec/02-compose-short-references.ja.md#用語)に従う。`> "a"` は、すでに AST 上でノード名 `>` と文字列引数 `a` として表せる。レキサー、パーサー、ライター、KDL 文法の拡張は不要。構文として読めるだけではファイルを取り込まないため、composer に認識処理を追加する。

短縮形を、既存のファイル取込記法 `(<)file` と同じ単一ファイル展開処理へつなぐ。短縮形の拡張子補完と、従来のパスの扱いは分ける。

## 認識とパス処理

1. `parse_directive` で、型注釈がなく、名前が正確に `>` のノードを新しい単一ファイル参照として認識する。既存の `<` 型注釈による分岐は変えない。
2. パスとオプションを検証する。エラー表示に使えるよう、元の表記を保持する。
3. 短縮形のパスに拡張子がなければ `.kdl` を補い、あればそのまま使う。対象はパスの最後の要素であり、親ディレクトリ名のドットは拡張子に数えない。`Path` による正規化より前に、空文字列、NUL、末尾の区切りやドット、`.` / `..` を拒否する。ファイル名があることを確かめてから、`Path::extension` / `PathBuf::set_extension` を使う。これにより、ホスト OS の規則に従って `.shared` を `.shared.kdl` に補完できる。
4. 補完した要求を、参照元ファイルのディレクトリを基準に既存の単一ファイル処理で解決する。呼び出し側が読み込み元を指定する API を将来追加する場合は、その読み込み元を使う。
5. 再帰的に展開し、取り込んだトップレベルノードに共通のフィルター・名前変更・名前空間の接頭辞を適用してから、参照があった位置へ挿入する。循環は、解決後の読み込み元の同一性に基づいて検出する。

`parse_directive` は `(node.ty(), node.name())` で分岐する。`(None, ">")` の場合だけ `short_reference_path` を使い、既存の `(<)` 系ではパスをそのまま扱う。このヘルパーは、型注釈のない文字列の位置引数を一つだけ受け取り、実際に要求するパスを `DirectiveKind::File` として返す。

入力検証の診断には元の表記を、I/O の診断には補完後のパスを使う。その後のオプション解析と展開は共用し、新しい公開型や `ComposeError` の変更は加えない。

`a` と `a.kdl` のどちらを読むか、存在確認で選ばない。`> "a"` の要求先は常に `a.kdl` である。また、同じ参照が繰り返された場合も、それぞれの位置へノードを挿入する。キャッシュで二度目以降の展開を省かない。

## 既存の動作と今後の API

`compose(path)` と `from_path<T>(path)` のシグネチャ、明示的に feature を有効化する境界は変えない。通常の `Document::parse`、`from_str`、シリアライズは `>` をデータのノード名として扱い、ファイル I/O を行わない。

関連する GFP の案では、呼び出し側が管理する読み込み元に、参照の解決と実際の読み込みを任せる。最初のファイルの読み込みと glob の列挙もそこに含む。拡張子補完は決定的な要求の変換として行えるが、読み込み元を迂回して隠れたファイルシステム操作を追加してはならない。

アクセス方針と保存世代の一貫性は、読み込み元の責務である。読み込み前に正規化したパスを確認するだけでは、シンボリックリンクをたどらないことや、一貫した世代を読むことは保証できない。

依存関係レポートでは元の要求と解決後の読み込み元を区別し、エラーには参照元と要求先を含める。公開する型の詳細は別の設計で決める。既存ファイルシステム glob の厳密な走査は[設計 03](03-fallible-glob.ja.md)で扱う。

## 受け入れ条件と検証

`tests/compose_short_references.rs` で次を確認する。

- `> "a"` と `> "./a.kdl"` が、`(<)file "./a.kdl"` と同じ文書を生成する。
- 短縮形でも、既存の単一ファイル参照と同じオプションと適用順序を使う。
- 入れ子の参照と、取込先からさらに行う参照が、各参照元を基準に解決される。元の順序、繰り返しの取込、通常の兄弟ノードを保つ。
- `a` と `a.kdl` が両方あっても `.kdl` を補完する。`a.kdl` がなければ、存在する `a` に切り替えずエラーにする。
- 明示的な拡張子を変えない。`(<)file "a"` は従来どおり拡張子なしのファイルを読む。既存の glob の挙動とは分けて扱う。
- `path`、`a`、`"a"`、引数や子を持たないノードはデータとして残す。型注釈のない、正確な名前 `>` だけを新しい参照とする。パーサーとライターの往復でもこの意味を保つ。
- 存在しないファイル、読めないファイル、構文解析エラー、既存記法と短縮形をまたぐ循環を検出する。
- 仕様 02 に挙げたパスと引数の境界条件を、OS 固有の区切り文字で確認する。
- `from_path<T>` で、展開後のノードをデシリアライズできる。

既存の compose テストも併せて実行し、文書に載せた記法は独立した KDL パーサーでも確認する。短縮参照の例には 0.16 以降が必要である。

新しいテスト群は本体変更前に実行し、未展開の `>` ノードに対して 16 件が失敗した。通常データの保持を確かめる 1 件は成功した。実装後は、新規 17 件と既存の統合テスト 25 件がローカルで成功した。

## 試作で確認した範囲

一時的な試作は、本体の `Document::parse` と小さな独自リゾルバーを使った。印を省く方式では、暗黙参照記法がデータと区別できないことを確認した。印を付ける方式では、`> "a"` の展開と、引数や子を持たない通常データの保持を確認した。

変更前の本体 composer で展開・エラーの確認 5 件がまず失敗し、試作の実装後に全 6 件が成功した。

試作プロジェクト `/tmp/club-kdl-shortest.GzNGmz` は一時的なもので、削除される可能性がある。ビルド依存や、リポジトリ内の回帰テストの代わりにはしない。既存のオプション・glob、独自リーダー、依存関係追跡、案件ごとのアクセス制限、保存世代の一貫性は扱っていない。この試作で本体のソースは変更していない。

## 避けること

- 引用符、引数や子を持たないノード、ファイルの有無から参照を推測しない。
- `>` を新しい KDL 演算子とみなしたり、独自のパーサー構文を要求したりしない。
- 過去に議論したという理由だけで、`(>)path` や `>path` を別名として追加しない。
- 短縮形の補完に合わせて、既存の拡張子なしパスの意味を変えない。
- 新しい記法のために、フィルターや名前変更を別実装にしない。
- 一時的な試作だけを根拠に、仕様の状態を「有効」にしない。
- 要求を検証する前に、末尾の `/.` を正規化で消さない。

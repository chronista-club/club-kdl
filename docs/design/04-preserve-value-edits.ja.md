**[English](./04-preserve-value-edits.md)** | 日本語

## 構成

`EditableDocument` は `String` を所有する。原文は既存の KDL v2 エンジンで検証する。
出力時は意味ツリーを整形せず、保持しているテキストを返す。公開している軽量 AST には、
書式のフィールドを追加しない。

編集のたびに、範囲を記録するパーサーの経路を使って、有効な entry の値のバイト範囲を
文書順に集める。ノード・entry の選択には解析した意味ツリーを使う。深さ優先で entry を
たどった順序は、範囲リストの順序に一致する。新しい値を既存の writer で書き、所有する原文の
該当範囲だけを置換する。次の編集では新しいテキストを再解析し、古い位置の再利用や自己参照を避ける。

通常のパーサーでは、範囲記録をコンパイル時に無効化する。編集モジュールと範囲を返す入口は
`edit` feature のときだけ有効になる。依存は追加しない。

## 原文の範囲

- 値の範囲は、プロパティのキー、`=`、型注釈、それらの間の空白・コメントより後から始め、
  値トークンの末尾で終える。
- 型注釈のない文字列引数では、元の引用符や raw 文字列の区切りも範囲に含める。
- `/-` ノードや子ブロックを破棄するときは、その中で記録した範囲も破棄する。
  `/-` entry は範囲リストへ追加しない。
- 重複プロパティは `Node::prop` と同じく右端を選ぶ。

## やってはいけないこと

正規表現で値を探さない。ツリー全体を書き直さない。既定 AST にコメント用フィールドを
追加しない。前の編集で取得した位置を使い回さない。参照先ファイルの変更を推測したり、存在しない
対象を自動作成したりしない。index は有効ノード・引数だけを数える。置換対象の値は正規化して
よいが、それ以外のトークンは変えてはならない。

## 通常経路の性能確認

Apple Silicon、Rust 1.96.0 で、既存の `parse/club-kdl` ベンチマークをパーサー変更前後に比較した。
各入力で warm-up 1 秒、測定 3 秒、50 サンプルを使った。

```sh
cargo bench --bench kdl_vs_json -- 'parse/club-kdl' --warm-up-time 1 --measurement-time 3 --sample-size 50 --save-baseline before-edit
cargo bench --bench kdl_vs_json -- 'parse/club-kdl' --warm-up-time 1 --measurement-time 3 --sample-size 50 --baseline before-edit
```

Criterion による平均時間の変化は、小さい入力で +0.17%（95% 区間 -0.28%〜+0.57%、p=0.45）、
大きい入力で -0.39%（-0.95%〜+0.17%、p=0.18）。どちらも有意な変化は検出されなかった。
これは手元での `Document::parse` の確認であり、コストが必ずゼロであるという保証や、編集 API
自体の性能測定ではない。

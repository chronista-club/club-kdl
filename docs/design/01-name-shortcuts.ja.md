# 01. 名前を短縮するコーデック

**[English](./01-name-shortcuts.md)** | 日本語

> **状態**: 有効（v0.15.0）
> **関連**: [仕様 01](../spec/01-name-shortcuts.ja.md)、`mem_1CgYBNbHDqGGdtK66QsMCL`
> **対象**: `src/compact.rs`、`src/write.rs`、`tests/compact.rs`、`tests/compact_spec.rs`、`benches/name_shortcuts.rs`

`compact` モジュールは、既存の KDL ツリー・パーサー・ライターの上に置き、明示的に有効化して使う。`KdlSerialize::to_kdl_doc` と `KdlDeserialize::from_kdl_doc` を利用し、derive の動作や通常の出力は変えない。正しさと明確な形式を優先し、ツリー構築や辞書検索のコストは測定して評価する。

## 名前対応表

`NameTable` は、使用を許可するすべてのノード名・プロパティ名について、双方向の順序付き対応表を所有する。短縮しない名前も表に含める。コンストラクタには、名前の集合、文書、シリアライズ可能な値を渡せる。元の名前を UTF-8 のバイト順に並べ、重複を除くことで、走査順序や出現回数に依存しない割り当てにする。

エイリアス候補は `a..z`、`A..Z`、`aa..az`、`aA..aZ`、`ba..` の順に列挙する。引用符が必要な KDL キーワード（`inf`、`nan` など）は飛ばす。元の名前をすべて予約したうえで、KDL にシリアライズした表記が 3 バイト以上、かつエイリアスより長い名前だけを短縮する。生成したエイリアスが元の名前と一致することはない。短い名前は、変換前後が同じ対応として保持する。読み込む表は一対一の対応でなければならず、別の元の名前と衝突するエイリアスは拒否する。

対応表の標準的な出力には、インデントを省いた共通ライターを使う。エントリは元の名前順に並べる。

```kdl
kdl-names 1 {
a object_identifier
b record_update
x x
}
```

各子ノードは、送受信に使う名前をノード名とし、元の名前を型注釈のない文字列引数一つで表す。数字や特殊な文字を含む名前にも、KDL の文字列エスケープを使う。ヘッダーの引数は、型注釈のない整数のバージョン一つだけで、プロパティと型注釈は持たせない。表の子ノードにもプロパティ・型注釈・孫ノードは認めない。送受信用の名前または元の名前が重複したらエラーにする。

対応表 ID は、次のバイト列全体の SHA-256 を小文字の十六進数で表す。

1. 接頭辞 `club-kdl:compact:1\0`。
2. 元の名前の UTF-8 バイト順に並べた、元の名前とエイリアスの組。各文字列の前には、その UTF-8 バイト長を符号なし 64 ビットのビッグエンディアン整数で置く。

この ID は KDL の空白や引用方法に依存しない。ハッシュへの入力は内部処理用であり、KDL 以外の通信形式を追加するものではない。`sha2` は `compact` を有効にした場合だけ使う。

## メッセージとファイル

共有表を使うメッセージは、ヘッダーの後にペイロードのノードを置く。

```kdl
kdl-message 1 "<64-character table ID>"
b a=42 x=10
```

メッセージヘッダーの引数は、型注釈のない整数のバージョンと、文字列の対応表 ID の二つだけ。子ノード・プロパティ・型注釈は持たせない。受信側は名前を解決する前に、バージョンと対応表 ID を検証する。プロトコル用のメタデータとして扱うのは先頭のノードだけであり、ペイロードではプロトコルの名前に似たものも含め、任意の元の名前を使える。

自己完結ファイルには、対応表と、その後に続くペイロードを含める。重複するメッセージヘッダーや表のハッシュは付けない。`compact::to_string/from_str` はオブジェクト、`compact::encode_document/decode_document` は任意の文書を扱う。表を再利用する場合は `NameTable::encode/decode` または `encode_document/decode_document` を使う。表だけの KDL は `to_kdl/from_kdl` で読み書きする。

実装は一時的なツリーの所有権を受け取り、ノード名・プロパティ名に当たる `Cow` の文字列だけを置き換える。共有表からのデコードでは、展開後の名前を表から、値を入力から借用できる。自己完結文書のデコードでは、一時的な表が処理後に破棄されるため、結果の文書がデータを所有する。

`CompactError` は通常の KDL エラーを包むとともに、表やメッセージ形式の不正、未対応バージョン、表の不一致、未知の名前を区別する。途中までの結果は返さない。簡便 API は、呼び出しごとに新しい文字列を確保する。

## 構造を表す空白

コンパクト出力には、コンパイル時にインデントの有無を切り替えられる既存の AST ライターを使う。ノードの再帰的な書き込みと、値・識別子のエスケープ処理は共通である。通常の AST 出力と derive が使う `NodeWriter` は、入れ子の階層ごとに空白 4 文字を入れる。コンパクト形式の入口だけが、表とペイロードのインデントを省く。新たな公開書式 API や依存関係は追加しない。

改行、`{` の前の空白、中括弧は残す。これにより、別の通信形式を設けずに KDL のノード終端と階層を保つ。リーダー、形式バージョン 1、対応表のハッシュは変えない。以前のインデント付きコンパクト文書も引き続き読める。

値には従来と同じ引用・エスケープを使う。シリアライズ後に各行をトリムすると、複数行の文字列値を壊すため、その方法は使わない。デコードした文書の `to_string()` は、通常の読みやすい書式を出力する。入力時の正確な書式やコメントは復元しない。

## 避けること

- 文字列置換で値や型注釈を短縮しない。
- 専用 API の明示的な呼び出しなしに、通常の KDL をコンパクト形式として解釈しない。
- 未知の名前をそのまま通さない。将来の元の名前とエイリアスが衝突する可能性がある。
- メッセージの順序から相手の対応表を推測しない。ハッシュ値をメッセージ認証コード（MAC）として扱わない。
- 固定名のベンチマークから、実行時に辞書を使う実装の性能を推定しない。
- サイズ比較から、通信の付加情報や対応表の交換コストを除外しない。
- 引用符が必要な名前を、引用前の長さだけで比較しない。自動割り当てではキーワードを避ける。
- ライターの出力レイアウトをハッシュしない。定義したバージョンと長さ付きの名前の組を使う。
- シリアライズ済みの入力を行ごとにトリムしたり置換したりして空白を削らない。構造を書き出す段階でインデントだけを省く。
- 構築済み AST の小規模測定を、コーデック全体の高速化として示さない。

# 03. 失敗を取りこぼさない glob 走査

**[English](./03-fallible-glob.md)** | 日本語

> **状態**: 有効。v0.16.0 のリリースに収録し、公開状況はリリースワークフローで管理する
> **関連**: `mem_1CgfiKufKrUCVb7phQzr1c`、[仕様 02](../spec/02-compose-short-references.ja.md)
> **対象**: `src/compose/glob_expand.rs`、`src/compose/mod.rs`、`src/compose/error.rs`、`tests/compose_glob.rs`、`tests/compose_glob_compat.rs`

## 問題と保証する動作

従来の composer は、`filter_map(Result::ok)` で `glob::GlobError` を捨て、`Path::is_file()` でもメタデータ取得の失敗を見落としていた。さらに glob 0.3.3 のイテレーターは、ワイルドカードを含まないパスの参照やディレクトリ判定の失敗の一部を、内部で「一致なし」に変えてしまう。イテレーターが返すエラーを伝播させるだけでは、すべてのケースを直せない。

修正対象は既存の `(<)glob` である。一致がない場合や、指定したパスの候補が実際に存在しない場合は、引き続き正常な空結果とする。一方、ディレクトリの探索、マッチした項目のメタデータ取得、リンク先が失われたシンボリックリンク、ファイルの読み込み・構文解析で失敗したら、合成全体を中止する。途中まで展開した文書を `Ok` として返さない。

公開関数のシグネチャと `ComposeError` の variant は維持する。不正なパターンは参照元のパスを含む `Glob`、ファイルシステムの失敗は失敗したパスと元の `io::Error` を含む `Io` で返す。ディレクトリを再帰走査する際の循環は `InvalidInput` を持つ `Io` とする。ファイルの内容に書かれた取込参照の循環には、従来どおり `Cycle` を使う。

## 走査の実装

パターンの検証と名前の照合には `glob::Pattern` を使い続ける。ファイルシステムの列挙とメタデータ取得は、非公開の `glob_expand` モジュールで行う。依存クレート、KDL パーサー、公開 API は増やさない。

- まずパターン全体を検証し、OS 固有のプレフィックス、ルート、`.`、`..` を保ってパス要素に分割する。参照元のディレクトリは文字どおりの基準パスとして扱い、パターンとして再解釈しない。
- ワイルドカードを含まない要素は、ディレクトリ一覧の取得権限を要求せず、直接メタデータを参照する。`NotFound` / `NotADirectory` の場合は `symlink_metadata` を使い、存在しない候補とリンク先が失われたシンボリックリンクを区別する。それ以外のエラーも呼び出し側へ伝える。
- ワイルドカードを含む要素は、ディレクトリを列挙して名前を照合し、一致した項目を調べる。一致後に項目が消えた場合はエラーとする。ディレクトリの列挙途中のエラーには、親ディレクトリのパスを付ける。
- `MatchOptions::new()` を使う。`Default` では大文字・小文字の扱いが異なる。大文字と小文字を区別する照合、隠しファイル名、リテラルのドットで始まるパターンによる仮想的な `.` / `..` への一致を維持する。
- `**` は別に処理する。連続する再帰要素はまとめる。末尾の `**` が一致するのはディレクトリだけなので、compose の取込対象からは除く。後続の要素は、再帰の各階層と、階層を一つも降りない場合の子に対して照合する。
- ディレクトリへのシンボリックリンクはたどる。正規化したディレクトリの履歴は、現在の再帰要素について、いま走査中の経路だけで保持する。別のパターン要素へ進んだら履歴をリセットする。同じ経路で同じディレクトリを再訪した場合は循環だが、別の経路から別名で到達した場合は循環ではない。
- 非 UTF-8 名については glob の既存の扱いを保つ。通常のワイルドカードは非 UTF-8 の名前には一致しない。ただし再帰走査では、そのようなディレクトリを通って、下にある UTF-8 名へ到達できる。Windows では、未対応の verbatim prefix に対して空結果を返す既存の動作を維持する。verbatim 形式のドライブパスには対応する。
- ディレクトリを除外し、最後にパスをソートする。同じパスが複数回現れた場合も残す。正規化後の同一性で重複を除いたり、拡張子を補完したりしない。

Rust の関数を再帰呼び出しする代わりに、未処理の項目を明示的なリストで管理する。一致結果のリストを成功として返す前に、発生したエラーを伝える。その後の合成は、既存のファイル解決と、共通のフィルター・名前変更・接頭辞付加の処理を使う。

## 検証

最初の回帰テストでは、再帰探索中の読めないディレクトリ、探索できない親を持つリテラルパス、一致したリンク先切れのシンボリックリンク、ディレクトリのシンボリックリンク循環が、旧 composer に対して失敗した。

権限テストでは実際に権限を変更し、アクセスが拒否されることを確かめる。後片付け時には、途中で処理が失敗しても権限を復元する。Unix の権限テストは特権のある UID 0 では明示的にスキップする。これは Windows ACL の検証を行ったという意味ではない。

既存動作の回帰検証には、拡張子が混在する候補、file → glob → file の相対解決、元の順序、オプション、周囲の兄弟ノード、本当に一致がない場合、ディレクトリの除外、構文解析・読み込みの失敗、取込の循環を含める。正常に一致するパターンは、既存 glob イテレーターとの比較でも確認する。比較には再帰パターン、ドットを含むパターン、シンボリックリンクによる別名を含む。

失敗時の動作を厳格にするのは意図した変更であり、リリースノートに記す。この修正自体は、仕様 02 の短縮参照や、呼び出し側が読み込み元を管理する API を実装するものではない。

## 限界と避けること

- 保証するのはエラーの伝播であり、ファイルシステムのトランザクションではない。並行した変更によって観測結果は変わり得る。スナップショットや no-follow は保証しない。
- メタデータの取得失敗を「ファイルではない」として捨てない。存在確認を使って、失敗した探索を黙って一致ゼロに置き換えない。
- 走査全体で共有する訪問済み集合を使わない。正当な別名経由の取込まで除外してしまうためである。
- glob に拡張子補完や新しいディレクティブ構文を追加しない。

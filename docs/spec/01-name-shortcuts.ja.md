# 01. 明示的に選択する名前の短縮

**[English](./01-name-shortcuts.md)** | 日本語

> **状態**: 有効（v0.15.0）
> **関連**: `mem_1CgYBNbHDqGGdtK66QsMCL`、[設計 01](../design/01-name-shortcuts.ja.md)
> **対象**: `src/compact.rs`、`tests/compact.rs`

## 目的

機械が扱う KDL メッセージや保存文書で、繰り返し現れるノード名とプロパティ名を短縮する。人が編集する設定ファイルと既存のシリアライズ API では、読みやすい元の名前を使い続ける。

表現には通常の KDL v2 を使い、独立したパーサーでも読めるものとする。名前の短縮は KDL の上に設ける語彙の取り決めであり、新しい構文は加えない。

## 要件

- `compact` feature と専用 API を明示的に選んだ場合だけ短縮する。既存の derive、通常の読み書き API とその出力は変更しない。
- 変更するのはノード名とプロパティ名だけとする。値、型注釈、位置引数、順序、重複するプロパティ、文書のルートの意味は保つ。
- コンパクト形式の対応表・メッセージ・ファイルでは、構造を見やすくするためのインデントを省く。ノードの境界と階層は改行と中括弧で保ち、文字列値の中の空白は変えない。通常のライターではインデントを維持する。リーダーは形式バージョンや対応表 ID を変えずに、インデントあり・なしの両方を受け入れる。
- ASCII の英字を使い、同じ入力には同じエイリアスを割り当てる。短いものから順に使い、必要に応じて 2 文字以上へ伸ばす。衝突を防ぐため、元の名前はすべて予約する。シリアライズ後の UTF-8 表現が 3 バイト以上で、かつエイリアスが元より短い名前だけを置き換える。
- 再利用可能な名前対応表により、メッセージを個別に受信しても解釈できるようにする。名前の欠落、未知のエイリアス、対応表の不一致は明示的にエラーにし、別のフィールドとして誤って解釈しない。表は不変とし、使う名前が変わったら呼び出し側が新しい表を作る。
- コンパクト形式で保存する文書には対応表を含め、過去の接続情報や外部レジストリがなくても復元できるようにする。小さな入力ではサイズが増える場合がある。コンパクト形式の選択は、必ず小さくなることを保証しない。
- 対応表とメッセージには形式バージョンを持たせる。未対応のバージョン、不正または曖昧な表のエントリは拒否する。
- 対応表 ID は偶発的な不一致を検出するために使う。メッセージ認証には使わない。
- 実際のオブジェクトの読み書きの往復、任意の文書の意味の保持、独立した KDL パーサーでの読み込み、衝突・エイリアス候補の使い切り、不正入力、既定 API の安定性を検証する。
- 実装したエンコード・デコード経路を、対応表の処理とヘッダーなどの付加情報も含めて測定する。バイト数の削減、CPU コスト、固定名を使った基準実験の結果は分けて報告する。

## 対象外

値や型名の圧縮、設定ファイルの移行、通信・セッション管理、スキーマの取り決め、暗号化・認証、圧縮コーデック、ファイル I/O、使用中の辞書の自動拡張、元の書式の保存、1 行化や最小サイズの KDL 出力は扱わない。

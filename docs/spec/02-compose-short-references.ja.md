## 用語

記法の名称は次のとおりとする。

| 書き方 | 日本語名 | 英語名 | 状態 |
|---|---|---|---|
| `"a"` 単独を参照として扱う案 | 暗黙参照記法 | implicit reference | 不採用。通常のデータとして扱う |
| `> "a"` | 短縮参照記法 | short reference | v0.16.0 に実装 |
| `(<)file "./a.kdl"` | ファイル取込記法 | file import | 既存の機能 |

「短縮参照記法」または「短縮形」は、参照を示す `>` を含む `> "a"` 全体を指す。「暗黙参照記法」は不採用になった案の名称であり、利用できる取込記法ではない。いずれも compose 上の取り決めで、KDL の文法を拡張するものではない。

## 目的

`> "a"` という短縮参照記法で、一つの KDL ファイルを取り込めるようにする。`>` によって参照であることを見分けられ、短く書ける。拡張子を省いた場合は `.kdl` を補い、相対パスは参照を書いたファイルのディレクトリを基準に解決する。

この処理を行うのは、明示的に有効化した composer だけである。`>` はノード名であり、型注釈や KDL の演算子ではない。通常の構文解析やデシリアライズで、別のファイルを読むことはない。KDL 仕様の[ノード](https://kdl.dev/spec/#name-node)、[識別子文字列](https://kdl.dev/spec/#name-identifier-string)、[型注釈](https://kdl.dev/spec/#name-type-annotation)も参照。

## 使い方

次のファイルがあるとする。

```text
case/
  plan.kdl
  共通仮設.kdl
  内装.kdl
```

`plan.kdl` は次のように書ける。

```kdl
estimate "案A" {
    > "共通仮設"
    > "内装"
}
```

各参照は、その位置で参照先を再帰的に合成したトップレベルノードに置き換わる。外側の `estimate` は残る。取り込んだファイル内の相対参照は、そのファイル自身の場所を基準に解決する。最初の `plan.kdl` や、プロセスの作業ディレクトリを基準にはしない。

| `case/plan.kdl` に書いた参照 | 読み込むファイル |
|---|---|
| `> "a"` | `case/a.kdl` |
| `> "./a"` | `case/a.kdl` |
| `> "parts/a"` | `case/parts/a.kdl` |
| `> "./a.kdl"` | `case/a.kdl` |
| `> "a.data"` | `case/a.data`（内容は KDL として読む） |

拡張子補完はファイルの有無に左右されない。拡張子のない `a` が存在しても、`> "a"` が読むのは常に `a.kdl` である。別名へのフォールバック、検索パス、環境変数の展開、ディレクトリの自動取り込みは行わない。

## 要件

- 型注釈がなく、名前が正確に `>` であるノードを単一ファイルへの参照として認識する。引数は型注釈のない文字列のパス一つだけとする。位置引数の不足・過剰、型注釈付きの引数、文字列以外の引数はエラーにする。
- 拡張子の補完は新しい短縮形だけに適用する。明示された拡張子はそのまま使い、`.kdl` に置き換えない。
- トップレベルと入れ子の両方で参照を使えるようにし、挿入位置と元の順序を保つ。同じファイルを二度参照したら二度展開する。展開中の参照経路が循環した場合はエラーにする。
- 既存の単一ファイル展開とオプションの意味を共用する。適用順序は `only` / `except`、`rename`、`as` とする。対象は取り込んだトップレベルノードの最初の文字列引数であり、内部にある任意の相互参照までは書き換えない。
- 既存の `(<)file` と、正常に処理できる `(<)glob` の挙動を維持する。パスとパターンは従来どおり扱い、どちらにも暗黙の `.kdl` 補完を加えない。glob の失敗時の扱いは[設計 03](../design/03-fallible-glob.ja.md)で定める。
- `path "./output.kdl"`、`a`、`"a"`、`enabled` は通常のデータとして残す。似た名前のファイルが存在するかどうかで、参照の判定を変えない。
- 単一ファイルのパス解決・読み込み・構文解析の失敗と、取込の循環はエラーとして返す。そこまでに展開できたノードを成功結果として返さない。glob の走査失敗も、既存の [glob 修正](../design/03-fallible-glob.ja.md)に従って伝播させる。ただし、ファイルシステム全体の一貫したスナップショットを保証するものではない。

次の例では出力先のパスをデータとして残し、`a.kdl` を取り込む。

```kdl
export {
    path "./output.kdl"
    > "a"
}
```

## パスの検証

- 空のパス、NUL を含むパス、OS のパス区切りで終わるパス、最後の要素が `.` / `..` のパス、最後の要素がドットで終わるパスは拒否する。ルートやプレフィックスだけでファイル名がない場合も無効。末尾の `/.` がパス正規化で消えないよう、元の表記を先に検証する。
- `.shared` のように拡張子のないドットファイルは `.shared.kdl` になる。親ディレクトリ名にあるドットは拡張子に数えない。`a.data` など明示的な拡張子は変更せず、内容は KDL として読む。
- 区切り文字と絶対パスの扱いは、実行する OS の規則に従う。`/` は全環境で区切りとなる。`\\` は Windows では区切り、Unix ではファイル名に含められる文字として扱う。サンドボックスや OS 間のパス変換は追加しない。
- 不正な短縮参照には、既存の `ComposeError::InvalidDirective` を使い、参照元ファイルと診断を返す。パス検証の診断には元の表記を含める。I/O の失敗には `ComposeError::Io` を使い、`.kdl` の補完後に実際に要求したパスを返す。構文解析エラーと循環は、従来のエラー variant を維持する。
- この検証は短縮参照のパスだけに適用する。既存の取込パスとオプションの検証は変えない。

## 互換性と検討した案

`(<)file` と `(<)glob` は引き続き利用できる。以前に検討した `(>)path` と `>path` は設計上の履歴であり、この仕様に追加する別名ではない。この検討の中で、どちらも本体の composer には実装していない。

暗黙参照記法、つまり `"a"` だけで参照を表す案は試作したが、採用しない。現在の AST は `"a"` と `a` を同じものとして扱う。そのため、引数や子を持たないノードを参照と解釈すると、`enabled` のような通常データも取り込んでしまう。`>` を明示することで、この曖昧さを避ける。

一方、新しい規約では compose 内の `>` という名前を予約する。**型注釈のない `>` ノードをデータに使っていた文書は、新しい composer で意味が変わる。** この点はリリースノートに明記する。パーサー自体の動作は変更しない。パスは読みやすさのため引用符で囲むことを勧めるが、引用符が取込の印になるわけではない。構文解析後のノード名と文字列値で判定する。

以前の `<` / `>` の議論は、「内容の取り込み」と「参照の解決」という意図を表したものである。生のテキストと解釈済みデータを厳密に分けるものではなく、既存の `<` ディレクティブも再帰的な解釈と変換を行っている。

## 範囲

この仕様で定めるのは、短縮参照記法と拡張子補完の規則である。ディレクトリの取り込み、新しい glob 構文、式の評価、自動書き戻し、トランザクション、ファイル監視は追加しない。

呼び出し側が管理する読み込み元と依存関係レポートは、関連する別の設計課題として残す。公開する Rust API の型はここでは決めない。既存 glob のエラー修正は[設計 03](../design/03-fallible-glob.ja.md)で扱う。案件ごとのアクセス制限、シンボリックリンクをたどらない I/O（no-follow）、保存世代の一貫性は GFP 側が担当する。

記法の実験時に未確定だったパス・引数の境界条件は、上記の規則で定める。呼び出し側の I/O と依存関係レポートに関する公開 API は、今回の実装には含めない。

## 検証と実装状況

隔離した試作では、`"a"` と `> "a"` を実際の `a.kdl` のノードに展開した。6 件の確認で、入れ子の展開と順序、引数や子を持たないノードとの衝突・保持、引用符の有無による同一性、ファイルの不存在、循環を扱った。採用したのは明示的な印を使う方式だけである。この試作だけでは、本体における既存ディレクティブ、オプション、glob、独自 I/O、依存関係レポートの対応を証明しない。

現在の実装には、実際の一時ファイルを使う `tests/compose_short_references.rs` と、既存の compose テストがある。追加するのは明示的な短縮参照だけで、パーサーと AST の変更は不要。暗黙参照は、ユーザーが最終的に選んだ範囲から除外している。

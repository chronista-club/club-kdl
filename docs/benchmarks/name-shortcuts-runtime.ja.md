# 自動エイリアス: 実装したコーデックの処理時間

**[English](./name-shortcuts-runtime.md)** | 日本語

この記録は、インデント付きの初期コーデック `adcef50`（`3f10721` としてマージ）の測定結果である。v0.15.0 でインデントを省く前の値を示す。その後の出力サイズと実装 API の比較は、[インデント省略の測定](indent-pack.ja.md)を参照。

このコーデックはバイト数を減らすが、今回の入力では**エンコード・デコードの時間は短縮しない**。実行時のツリー構築と辞書検索により、変更していない通常 API より処理時間が増える。[固定名を使った初期実験](name-shortcuts.ja.md)は、コンパイル時に対応が決まる別の経路を測ったものであり、そこでの高速化をこの実装に当てはめることはできない。

測定日は 2026-10-30。Apple M5、macOS 27.2 (26B123)、rustc 1.96.0、最適化した Cargo bench プロファイル、Criterion 0.8.2 を使用した。全 21 測定の各条件は、60 サンプル、ウォームアップ 500 ms、測定 2 秒。共有の開発マシンで 1 回測定し、通常 API も同じ実行内で測り直した。このセッションから、ほかのテスト・ビルド・ベンチマークは同時に起動していない。

入力は初期実験と同じで、8 バイトの値を持つ 1 レコード、同じく 100 レコード、`x` を 4096 バイト繰り返した値を持つ 1 レコードの 3 種類。人工的なデータであり、実際の本番通信を採取したものではない。処理時間には出力結果の破棄を含める。単位は 1 バイト当たりではなくメッセージ全体であり、プロセス全体の CPU 時間ではなく経過時間を測っている。

- `normal`: 通常の `to_string/from_str`。読みやすい元の名前を使う。
- `shared`: `NameTable::encode/decode`。表の構築は測定時間に含めないが、メッセージヘッダー、ツリー構築、名前の検索、構文解析、元の名前への展開は含める。
- `file`: `compact::to_string/from_str`。表の作成・読み込み、検証、ハッシュ計算、毎回の表の書き込みと解析を含める。

すべての形式で同じ Rust の型へ復元でき、`kdl-rs` でも解析できる。[生の測定結果](name-shortcuts-runtime-results.csv)には、推定方法と 95% 信頼区間を保存している。推定値は Criterion の回帰直線の傾きで、flat sampling の場合は平均値を使う。以下の相対変化は点推定同士の比較であり、対応のある統計検定ではない。削減率が負なら、出力サイズは増えている。

| 入力 | モード | 通信・ファイルのバイト数 | 削減率 | シリアライズ µs | デシリアライズ µs |
|---|---|---:|---:|---:|---:|
| small | normal | 227 | 0.0% | 0.196 | 0.513 |
| small | shared | 163 | 28.2% | 0.575 | 0.695 |
| small | file | 323 | -42.3% | 3.548 | 3.379 |
| batch100 | normal | 16,178 | 0.0% | 15.346 | 33.055 |
| batch100 | shared | 6,016 | 62.8% | 25.363 | 36.872 |
| batch100 | file | 6,176 | 61.8% | 41.509 | 39.541 |
| payload4k | normal | 4,315 | 0.0% | 1.334 | 2.131 |
| payload4k | shared | 4,251 | 1.5% | 1.803 | 2.535 |
| payload4k | file | 4,411 | -2.2% | 4.734 | 4.933 |

表の構築時間は、small が 2.579 µs、batch100 が 22.590 µs、payload4k が 2.575 µs。

実際の対応表は 241 バイトである。この入力の共有メッセージには 81 バイトのヘッダーが含まれる。表の交換には別途コストがかかり、再利用によって 1 メッセージ当たりの負担が小さくなる。自己完結ファイルは表を埋め込み、重複するメッセージハッシュやヘッダーは持たない。初期の固定名実験で例示した 270 バイトの辞書とは形式が異なる。

small の共有メッセージは、通常 API と比べてシリアライズに約 2.9 倍、デシリアライズに約 1.4 倍の時間がかかる。100 レコードでは、それぞれ約 1.7 倍と 1.1 倍。表を毎回扱う自己完結形式では、さらに負担が増える。共有コーデックが AST を構築して名前を置き換えるのに対し、通常の derive ライターはテキストを直接出力する。

保存時のサイズは、100 レコードなら 16,178 → 6,176 バイトで、61.8% 減る。一方、small の自己完結ファイルは 227 → 323 バイトに増え、4KB の値が大半を占める文書も増える。名前が何度も現れる保存データにはコンパクト形式が向く。人が読む設定には通常 API を使い、採用するアプリケーションで CPU コストとバイト削減の釣り合いを測る。

将来、ライターやパーサーへ直接組み込めば負担を減らせる可能性はあるが、この版では実装していない。通信方式の取り決め、ここで扱う KDL 形式以外のパケット付加情報、圧縮した通信量、実際のネットワークの遅延とスループットは測定対象外。

## 再現方法

```sh
mkdir -p target/name-shortcuts
KDL_SHORTCUT_ARTIFACTS=target/name-shortcuts/inputs \
  cargo bench --bench name_shortcuts -- name_shortcuts_runtime --noplot \
  > target/name-shortcuts/runtime.log 2>&1
```

時間を測らずにアサーションと各経路の動作を確認するには、`cargo bench --bench name_shortcuts -- --test` を実行する。入力とログは `target/name-shortcuts`、Criterion のサンプルと推定値は `target/criterion/name_shortcuts_runtime_*` に出力される。

実装と形式の詳細は[設計 01](../design/01-name-shortcuts.ja.md)と[使い方のガイド](../guide/01-compact-names.ja.md)を参照。
